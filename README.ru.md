# ManipStudio

**Настройте робота. Спланируйте движение. Посмотрите нагрузки.**

Инженерное приложение на C++ с интерактивной 3D-моделью,
планированием траекторий и расчётом моментов в суставах.

![ManipStudio: 3D-робот, путь TCP, программа движений, графики моментов и пиковые нагрузки](docs/images/manipstudio.png)

ManipStudio объединяет настройку модели, команды движения и анализ результатов
в одном окне. Задайте положение суставов, постройте прямую или дугу, затем
перемещайте бегунок времени: положение робота и курсор графиков меняются вместе.

Репозиторий носит историческое имя **MainKinematic**, приложение — **ManipStudio**.
Сейчас поддерживается последовательный манипулятор с **шестью вращательными суставами**.

## Возможности

| Модель | Движение | Анализ |
|:---|:---|:---|
| Модифицированная таблица DH | Синхронный **MoveJ** | Интерактивный 3D-вид и путь TCP |
| Пределы углов, скоростей и ускорений | Прямолинейный **MoveL** | Углы, скорости и ускорения суставов |
| Массы, центры масс, инерции звеньев | Дуга **MoveC** через среднюю точку | Моменты и отношение пиков к пределам |
| Точечный груз и плоскость пола | Шаги TCP и программа J/L/C | Воспроизведение и экспорт CSV |
| Выпуклые коллизионные оболочки | Контроль столкновений и моментов | Русский и английский интерфейс |

Геометрия для отображения и проверки столкновений строится из общего описания
звеньев. Радиусы суставов настраиваются. Расчёт траекторий выполняется в отдельном
потоке. Окно **«Моторы»** позволяет отдельно тестировать симулятор ODrive;
поддержка настоящих приводов по CAN пока экспериментальная.

## Сборка и запуск

Нужны компилятор C++17, CMake и Qt **6.4+** с Quick, Quick Controls, Quick 3D,
Charts и Qt Test. Команды выполняются из корня скачанного репозитория.

### Linux / Ubuntu 24.04

```bash
sudo apt update
sudo apt install -y build-essential cmake ninja-build git \
  qt6-base-dev qt6-declarative-dev qt6-quick3d-dev qt6-charts-dev \
  qt6-shadertools-dev libxkbcommon-dev \
  qml6-module-qtquick qml6-module-qtquick-controls \
  qml6-module-qtquick-layouts qml6-module-qtquick-window \
  qml6-module-qtquick-dialogs qml6-module-qtquick-templates \
  qml6-module-qtqml-workerscript qml6-module-quick3d \
  qml6-module-quick3d-helpers qml6-module-qtcharts

cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel 8
./build/Studio/ManipStudio --lang ru
```

При первой настройке сборки скачивается GoogleTest. Для 3D нужен рабочий
графический бэкенд. В WSL приложение открывается через WSLg; программный
бэкенд Qt `offscreen` не отображает 3D-сцену.

### Windows / MSYS2 UCRT64

Установите [MSYS2](https://www.msys2.org/) и откройте терминал **UCRT64**.
Обновите систему командой `pacman -Syu`. Если обновление попросит закрыть
терминал, откройте UCRT64 заново и повторите команду. Установите зависимости:

```bash
pacman -S --needed \
  mingw-w64-ucrt-x86_64-gcc \
  mingw-w64-ucrt-x86_64-cmake \
  mingw-w64-ucrt-x86_64-ninja \
  mingw-w64-ucrt-x86_64-qt6-base \
  mingw-w64-ucrt-x86_64-qt6-declarative \
  mingw-w64-ucrt-x86_64-qt6-quick3d \
  mingw-w64-ucrt-x86_64-qt6-charts \
  mingw-w64-ucrt-x86_64-qt6-shadertools \
  mingw-w64-ucrt-x86_64-gtest

cmake -S . -B build-win -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DMANIP_SYSTEM_GTEST=ON
cmake --build build-win --parallel 8
./build-win/Studio/ManipStudio.exe --lang ru
```

Запускайте приложение из UCRT64, чтобы Windows находила DLL Qt. Готового
дистрибутива с упакованными зависимостями пока нет. Проверена сборка MinGW-w64;
MSVC и macOS ещё не проверялись.

## Первая программа

В репозитории есть пример **J → L → C → L**:

```bash
./build/Studio/ManipStudio --lang ru \
  --program "$PWD/Studio/examples/demo_program.json"
```

В Windows используйте путь `./build-win/Studio/ManipStudio.exe`.

1. Выберите начальную позу ползунками или кнопками «Ноль» / «Сложенная».
2. Укажите тип движения и цель. «Текущие» копирует текущие значения.
3. Запустите отдельное движение либо добавьте несколько команд в программу.
4. Изучите путь TCP и графики, приостановите воспроизведение или переместите бегунок времени.
5. Экспортируйте значения в CSV, а программу сохраните в JSON.

На границах шагов предусмотрена остановка: скругления переходов между командами
пока нет. В файлах программ углы задаются в **градусах**, координаты — в **метрах**.
Поза записывается как `[x, y, z, roll, pitch, yaw]`, ориентация — ZYX Euler.

Полный [пример JSON](Studio/examples/demo_program.json) и
[справка по аргументам запуска](README.md#try-a-motion-program) доступны в репозитории.

## Настройки

Кнопка **«Настройки»** открывает редактор модели:

| Вкладка | Параметры |
|:---|:---|
| **Кинематика** | Таблица DH, радиусы суставов для 3D и коллизий |
| **Пределы** | Углы, скорости, ускорения, предельные моменты, высота пола |
| **Динамика** | Массы, центры масс, инерции звеньев, масса и положение груза |

«Применить» перестраивает модель в памяти, «Сохранить в файл» записывает
[ManipulatorSettigns.ini](ManipulatorSettigns.ini), «Перечитать файл» возвращает
сохранённые параметры. После изменения модели старая траектория очищается.
Историческое написание имени INI-файла сохранено для совместимости.

MoveJ учитывает пределы отдельных суставов, сохраняя синхронность.
MoveL и MoveC могут равномерно замедлить всё движение, чтобы удержать скорости
и ускорения суставов в пределах. Значения по умолчанию относятся к примеру,
включая **точечный груз 5 кг**, и требуют настройки под конкретного робота.

## Проверка

```bash
ctest --test-dir build --output-on-failure
```

В Windows замените `build` на `build-win` и используйте UCRT64. Без дисплея в Linux:

```bash
QT_QPA_PLATFORM=offscreen ctest --test-dir build --output-on-failure
```

Тесты охватывают математику, FK/IK, динамику, коллизии, траектории,
настройки, бэкенд GUI, геометрию, переводы и симулятор моторов. Результаты
кинематики и динамики сверяются с независимыми эталонами; отдельные сценарии
проверяют поведение движения при заданных начальных условиях.

## Моторы

Окно «Моторы» поддерживает симулируемые оси ODrive и экспериментальную
работу по CAN Simple. В нём есть настройка передаточного числа, направления
и нуля, включение, толчок, переезд в угол и графики обратной связи.

```bash
./build/Studio/ManipStudio --motor-sim
```

SLCAN через COM-порт требует Qt SerialPort, CAN-плагины — Qt SerialBus.
Настоящие приводы ещё не проверены; для физических испытаний нужны аппаратный
аварийный останов и настроенный watchdog привода. Команды программы робота
пока не передаются реальным моторам. Подробнее — в
[английской справке](README.md#motor-testing).

## Текущее состояние

- Поддерживаются шесть вращательных суставов. Переменное число осей и поступательные суставы — дальнейшая работа.
- Ориентация в декартовых движениях интерполируется по углам Эйлера; SLERP пока не реализован.
- Коллизии проверяются по приближённым выпуклым оболочкам в дискретных позах.
- Груз считается точечной массой; контактные силы на инструменте не рассчитываются.
- Проверялись Linux/WSL с Qt 6.4 и Windows/MSYS2 с Qt 6.11. Ядро также собирается на Qt 5.15.

Для сообщения об ошибке полезны файл модели, начальная поза, команда или
программа и ожидаемый результат. Для изменений поведения добавляйте
регрессионный сценарий и запускайте соответствующие тесты.
